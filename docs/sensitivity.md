# Regenerate principal electrophysiology sensitivities

First create a completed corrected run with `scripts/reanalyze_ephys.py`. Then:

```sh
python scripts/reproduce_sensitivity.py \
  --raw-dir .local/raw --run-dir .local/ephys --output .local/sensitivity
```

The numerical interpreter must have `requirements-ephys.txt` installed. Paths
are explicit and can be outside the checkout. No study-folder path, working
directory, network download or author module is required. `--output` must be
new or empty and must not overlap inputs or published files. Repeated `--fly`
options restrict a completed run to a named subset; the default processes its
entire selected population.

## Inputs and method

The command requires an `ephys-run/v2` `RUN.json` with `status: pass`,
`processing_status: completed`, `analysis_status: usable`, `selected_flies` and
per-record source hashes. The complete inventory and usable channel population
must match the run's selection and named neurons, including when a subset is
requested. A partial, excluded or legacy run is rejected.

Each selected original MAT file is checked against the run's MD5 and size (and
SHA256 when present). Aligned arrays must match inventory shapes, time, valid
duration, neuron/channel identity and raw clock epochs. Recomputed base counts
must agree exactly with saved counts; base rates and Vm must agree at
`atol=rtol=1e-10`. A mismatch fails the record before its sensitivity rows are
included. These checks establish input consistency with the supplied run;
they do not independently establish the provenance of an arbitrarily supplied
run receipt.

The generator uses the corrected core's per-epoch normalization, peak
extraction, rate smoothing and Vm filtering. Lagged correlations require both
ends to belong to the same epoch. The baseline masks remain in force at every
threshold. Every CSV row records `method_version: epoch-isolated-sensitivity/v2`.
`SENSITIVITY.json` records inputs and script hashes, versions, settings, row
counts, errors and the exact completed-run hash. It is a generation receipt,
not a comparison against the legacy published numbers.

## Output mapping

All rows are generated by the command above. Header-only tables are written
when the selected population does not contain an applicable pair or reset.

| Output | Inputs and retained definitions | Relation to archived `data/activity` |
| --- | --- | --- |
| `threshold_lag_sensitivity.csv` | Raw voltage, aligned mask/yaw; DNa02 baseline 7.5 times 0.75, 1, 1.25, 1.5, 2, 2.5; DNa01 baseline 5.75 times 0.75, 1, 1.25; lag sweep -500 to +500 ms by 10 ms | Corrected replacement for the same named legacy table |
| `paired_threshold_sensitivity.csv` | Paired rate difference against yaw at each shared multiplier; cross-type DNa02-to-DNa01 peak lag at DNa02 multipliers 1 and 2 | Corrected replacement; preserves the legacy row kinds and undefined `difference_r150` for cross-type lag-only rows |
| `pair_sensitivity.csv` | Bilateral DNa02 rates; left-minus-right, left-plus-right, each side and difference peak; all six multipliers | Corrected replacement; prominence 15 retains `source_notebook_example=True`; main eligibility is carried from both channels |
| `voltage_sensitivity.csv` | Baseline aligned rate, Vm and validity; exploratory pointwise Vm <= -33 mV; both channels must qualify for a pair | Corrected replacement; this cutoff does not reproduce the authors' exclusion decision |
| `clock_boundary_sensitivity.csv` | Reset records; baseline and source-example rates; extra 0.5 s and 5.5 s guards around each reset, retaining all existing validity exclusions | Extended replacement; legacy table contained only 5.5 s rows, so select `guard_s=5.5` for corresponding conditions |
| `source_example_comparison.csv` | DNa02 prominence 15, DNa01 prominence 5.75; threshold-grid correlation and estimability summaries | Corrected replacement for the same named legacy supplemental table |
| `source_example_aligned/*.npz` | Per-channel source-example counts and smoothed rates | Corrected intermediate used by the boundary analysis; not an archived base-run NPZ replacement |

The clock table preserves legacy method labels `baseline7.5` and
`source_example15` for correspondence. In both cases DNa01 uses 5.75; the labels
describe the DNa02 threshold. The guard excludes bin centers closer than the
named number of seconds to each reconstructed epoch boundary. A wider guard
cannot restore bins removed by stimulation, unknown stimulation or the base
run. For zero eligible bins or unestimable correlations, undefined values stay
NaN; they are never converted to zero.
As in the archived summary, `threshold_grid_sign_stable` considers only finite
correlations, including zero as its own sign; use the separate
`threshold_grid_all_estimable` boolean to know whether every threshold was
estimable.

The archived sensitivity definitions came from `threshold_lag_check.py`,
`pair_sensitivity.py`, `clock_boundary_sensitivity.py` and the independent
`verify_bundle.py` in the original research snapshot. The archived calculations
included joined-epoch peak extraction and smoothing. The public generator
preserves their settings and signal definitions while replacing those
operations with the corrected method. It therefore does not claim byte or
numerical identity with v1, and does not recreate unported waveform figures,
the local-MAD diagnostic or movement-proxy analyses.

## Failure and evidence scope

Preflight input or path errors emit JSON `status: error` and exit 2. Per-record
failures produce `SENSITIVITY.json` with `status: fail`, error details and the
successful subset, then exit 1. Such a directory is a failed/partial run even
when some CSV rows exist. Successful generation emits the receipt on stdout
and exits 0. Progress goes to stderr. Argument syntax errors use argparse's
stderr/exit-2 convention.

The JSON envelope has string `schema_version: fly-neuron-atlas-sensitivity-run/v2`
and string enum `status: pass|fail|error`. Generated receipts contain a `rows`
object of integer counts, an `errors` array of `{fly, message}` string objects,
input hashes, settings and string arrays `selected_flies`/`processed_flies`.
Preflight errors contain a string `message`. The exit code supplies the failure
category. A mismatch requires reconciling the input files with their completed
run or generating a new corrected base run; retry into a new output directory.

`tests/test_sensitivity.py` exercises the public command with synthetic MAT
voltages, a copied corrected base run, raw-hash and baseline-count faults,
selection mismatches, independent correlation calculations and explicit Vm
and clock masks. The base fixture uses the analysis core, so these tests check
the generation workflow and sensitivity definitions; they do not independently
validate the detector or biological conclusions.
